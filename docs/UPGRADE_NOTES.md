# 업그레이드 노트 — 백테스트-라이브 정합성 작업

이 문서는 이 프로젝트에 적용 중인 구조 개선 작업의 현황·근거·남은 일을 정리한다.
방법론 원본은 [TRADING_BOT_PLAYBOOK.md](TRADING_BOT_PLAYBOOK.md) 참조.
(작업 시작 2026-07-07. 별도 트레이딩 봇 프로젝트 `d:\Fable`의 설계를 이 봇에 이식하는 중.)

---

## 왜 이 작업을 하는가

이 봇의 Google Sheets '코인' 시트에 쌓인 실시간 시뮬 271건(2026-06~07, 수수료 반영)을
분석한 결과: **백테스트 기대값 +0.15%/거래 vs 실시간 시뮬 -0.45%/거래**.
이 괴리의 구조적 원인은 "백테스터와 라이브가 서로 다른 코드로 같은 판정을 중복 구현"한 것이었다.
→ 판정 로직을 **단일 구현으로 통일**해 괴리 원인을 제거하는 것이 이 작업의 목표.

원칙: **매매 동작을 바꾸지 않는다.** 결과가 동일함을 특성 테스트(characterization test)와
스모크 백테스트로 매번 확인하며 리팩토링만 한다. (라이브가 VPS에서 돌고 있으므로 빅뱅 재작성 금지.)

## 완료 (Phase A + B)

### Phase A — 검증 인프라
- **특성 테스트 41개** (`tests/`) — 현재 동작을 스펙으로 고정. 리팩토링 안전망.
  - 실행: `pip install -r requirements-dev.txt && python -m pytest tests`
  - `conftest.py`가 `GOOGLE_SHEETS_ID`를 비운다 — 안 그러면 `core.trader` 임포트만으로
    실제 Google Sheets에 연결되는 부작용이 있음(모듈 임포트 시점 접속).
- **backtest.py 진단 기능 추가**: 청산 사유별 손익 분해, `--split`(in/out-of-sample 분리),
  `--sweep-threshold`(과최적화 검증, OHLCV 캐시로 API 재호출 없음).

### Phase B — 드리프트 제거 (백테스트=라이브 단일 코드)
두 판정 로직이 각각 중복 구현돼 있던 것을 단일 구현으로 통일:

| 구분 | 단일 구현 | 공유하는 곳 |
|---|---|---|
| 청산 판정 | `core/exit_rules.py` (`judge_exit`, `net_profit_pct`) | trader.py + backtest.py |
| 진입 점수 가중치 | `core/scoring.py` (`weighted_score`, 장2.5/중2/단0.5) | data_builder.py 2곳 + backtest.py |

- 청산 회계를 **양방향 수수료 실수령 기준**으로 통일(과거 백테스터는 편도라 트리거가 ~0.1% 어긋남).
  이는 Sheets에 적재되는 `profit_pct`와 동일한 기준.
- 테스트가 `trader.judge_exit is exit_rules.judge_exit` 동일성과 legacy 수식 등가를 보증.
- 스모크 백테스트로 리팩토링 전후 결과 완전 동일 확인(15건, in +2.47% / out +1.61%).

### 1. [완료 2026-07-08] 파라미터 재검증 — 파라미터 축 소진 확정
`--days 180 --split 2026-05-01`로 기본·`--no-signal-exit`·threshold 스윕(8/10/12/14) 실행. 결과:

- **기본(th=12)**: 290건, EV -0.365% (in -0.606% / out -0.025%). 청산 분해:
  매도신호 141건 승률 9.2% 누적 -208.9%, 손절 33건 -145.5%, time-stop 94건 +98.5%, 익절 22건 +149.8%.
- **`--no-signal-exit` 기각**: EV -0.343%로 개선 미미, out은 -0.025%→-0.118% 악화.
  손실이 손절(33→61건, 누적 -273.5%)·time-stop 희석(+1.05%→+0.16%)으로 이전될 뿐.
  → 매도신호는 나쁜 포지션의 조기 절단 역할. **브래킷 문제가 아니라 진입 품질 문제.**
- **threshold 스윕**: 4개 × in/out 8칸 전부 음수 EV. in 최적(14)·out 최적(12) 불일치 — 일관 우위 없음.
- **결론**: 7/5 청산 스윕(24조합 전 음수)과 합쳐 파라미터 축 완전 소진. 파라미터 변경 없음(현행 유지).
  유일한 개선 경로는 섀도우 로그 기반 **진입 신호 재설계**(CLAUDE.md 채택 방향, 30건 축적 대기).

### 1.5 [진행 중] 신호 재설계 — 섀도우 실측 + BB 재검증 (2026-07-08)

섀도우 로그 52건 축적(목표 30건 초과) → 매수 shadow ↔ 매도 손익 FIFO 매칭 43건 분석:

- **bb_pct가 가장 강한 분리자**: 중앙값(51.3) 하위 승률 42.9%·평균 +0.32% vs 상위 31.8%·-0.56%.
  → 현행 점수제의 밴드 상단 가점(모멘텀)이 실측과 반대 방향. 7/2 실험 가설과 독립적으로 일치.
- **atr_pct 높을수록 열위**(-0.32% vs +0.07%) — 7/2 "ATR 하한 게이트"와 반대. 상한 게이트 후보.
- 손절 20건 전패(누적 -85.9%) — 진입 품질 문제 재확인.

백테스트 재검증(180d, split 2026-05-01): `--bb-mode off`가 방향성 우위
(in -0.606→-0.295%, **out -0.025→+0.134%**). flip은 과잉교정으로 열위.
`off` × threshold {10,12,14,16} 스윕 결과 **채택기준(두 구간 모두 양수) 통과 조합 없음** —
in 최적(16: +0.21%)과 out 최적(12: +0.13%)이 엇갈림(th16은 표본 54건으로 노이즈 가능성).

**결론**: 운영 코드 변경 없음. "BB 상단 가점 해로움"은 라이브+백테스트 이중 확인 —
섀도우 매칭 ~80건 축적 후 bb_pct 분위 분석 신뢰도를 높여 재판정.
분석 방법: 매수 shadow ↔ 같은 티커 다음 매도를 FIFO 매칭 → 피처별 중앙값 상/하 분위의 승률·평균 비교.

### 1.6 [채택 완료 2026-07-14] 신호 재설계 — BB 추격 가점 제거 + 임계치 13 + 시뮬 레짐 정합화

섀도우 매칭 78건 도달 후 재판정. 실측(bb_pct 하위 승률 43.6%·+0.579% vs 상위 28.2%·-0.807%)이
표본 확대 후에도 유지, 주식 백테스트(독립 시장)에서도 추격매수 열위 재현 → 방향 3중 확인.

백테스트 재검증(180d, split 2026-05-01) 결과:
- **pullback 가점 모드(신규 실험)**: 전 임계값·전 구간 음수 — 기각. 섀도우의 "눌림목 우위"는
  가점으로 옮기면 소멸(평균회귀 단독 엔진 실패와 동일 패턴).
- **레짐 게이트 단독(current+gate)**: out 전 임계값 음수 — BB 가점 제거가 필수 기여 요인.
- **bb-off + regime-gate**: th13 (in +0.12% / out +0.18%), th14 (in +0.09% / out +0.05%)
  **채택기준(두 구간 모두 양수) 최초 통과 + 이웃 연속 통과.** th12/15/16은 미달.

반영: `score_signal(ind, bb_mode)` 인자화(코인 "off", 주식 기본 "current" 무영향),
`BUY_SCORE_THRESHOLD` 12→13, 시뮬 레짐 필터 바이패스 제거(F&G 바이패스 유지),
backtest.py off 분기 단일 구현 위임 + `--threshold` 기본값 config 참조. 테스트 47개 통과.

**한계**: 폭이 얇음(구간당 표본 50~80건, EV +0.05~0.18%). "확실한 흑자"가 아니라
"-0.43%에서 본전 위 후보"로 간주하고 반영 후 라이브 시뮬 EV를 계속 추적할 것.
시뮬 회계 검증 결과: 거래별 profit_pct는 정확(양방향 수수료), sim_krw 잔고만
매수당 0.05% 이중 차감되는 표시용 버그 존재(EV 측정 무영향, 낮은 우선순위).

## 알아둘 것 (검증 중 발견)

- **RSI 특이점**: 손실 봉이 전혀 없는 순수 단조 상승/하락에서 RSI가 100/0이 아니라 50(중립)으로
  계산됨(`avg_loss=0 → NaN → fillna(50)`). 실전 영향 작지만 `test_indicators.py`에 고정해둠.
- **sheets_client 임포트 부작용**: `core.trader` 임포트 시 Sheets에 연결. 테스트는 conftest로
  차단. 향후 lazy-init로 개선 여지.
- **sheets_client 경고**: `worksheet.update()` 인자 순서 deprecation 경고(gspread 6.x). 기능엔 무해.
