## 실험 1 — 볼린저밴드(BB) 부호/조건 재검토

### 현 로직 (`core/analysis.py` 105–112행)
```python
if bullish:
    if bb_pct >= 0.8:   score += 1    # 상단 주행 = 강세 지속
    elif bb_pct <= 0.0: score -= 1    # 추세 이탈 경고
else:
    if bb_pct >= 1.0:   score -= 2    # 비추세 상단 이탈 → 매도
    elif bb_pct >= 0.8: score -= 1
```

### 문제 진단
- 현 로직은 "상승추세 + BB상단(≥0.8) 주행"에 +1을 준다. 이는 **이미 밴드 상단까지 오른 자리에서 추격 진입**을 유도 → 진입 직후 평균회귀 되돌림에 손절당하기 쉬움. 손절 116건 편중과 정합.
- 반대로 "상승추세 + BB하단(≤0.0)"에 -1(감점)을 준다. 상승추세에서의 밴드 하단은 오히려 **얕은 눌림 = 좋은 진입 위치**일 수 있음.

### 스펙: 3가지 변형을 백테스터 flag로 비교

`score_signal(ind, bb_mode="current")` 형태로 시그니처에 **기본값 인자** 추가(기존 호출부 무변경 보장). backtest.py에서 `--bb-mode` 인자로 주입.

- **`bb_mode="current"`** (현행, 대조군):
  위 코드 그대로.

- **`bb_mode="flip"`** (부호반전 — 상승추세 눌림목 매수형):
  ```python
  if bullish:
      if bb_pct <= 0.25:  score += 1    # 상승추세 밴드 하단 눌림 = 진입 기회
      elif bb_pct >= 0.95: score -= 1   # 밴드 상단 과열 = 추격 회피
  else:
      if bb_pct >= 1.0:   score -= 2
      elif bb_pct >= 0.8: score -= 1
  ```

- **`bb_mode="off"`** (BB 항목 완전 제거 — 노이즈 검증):
  BB 가·감점 블록 전체를 건너뜀. BB가 순수 노이즈면 이 변형이 `current`와 통계적으로 동등하거나 더 나음.

### 임계값 근거
- `0.25`/`0.95`는 밴드 폭의 하위 25%/상위 5% 위치. 표본이 작아 0.2~0.3, 0.9~0.95 사이 소폭 스윕은 param-optimizer에 위임(과적합 방지 위해 grid는 2점씩만).

### 백테스트 가능 여부: **O** (OHLCV만 필요, 추가 API 없음)

## 실험 2 — 변동성 하한 게이트 (최우선 권장)

### 목적
스테이블코인·변동성 극저 코인이 "추세도 노이즈도 없어" 점수가 요동치지 않고 임계치를 넘거나, 넘어도 익절폭(6%)까지 갈 변동성이 없어 flat 청산되는 문제를 **근본 차단**.

### 지표 추가: ATR% (`core/indicators.py`)
현재 ATR 없음. 다음 함수를 `indicators.py` 패턴에 맞춰 추가:
```python
def calculate_atr(df, period=14):
    """ATR (Average True Range). 반환: ATR 절대값 Series."""
    high, low, close = df["high"], df["low"], df["close"]
    prev_close = close.shift(1)
    tr = pd.concat([
        high - low,
        (high - prev_close).abs(),
        (low - prev_close).abs(),
    ], axis=1).max(axis=1)
    return tr.ewm(alpha=1/period, adjust=False, min_periods=period).mean()
```
`add_all_indicators()`에 추가:
```python
df["atr"] = calculate_atr(df)
df["atr_pct"] = (df["atr"] / df["close"].replace(0, np.nan) * 100).fillna(0.0)
```
`get_latest_indicators()` 반환 dict에 `"atr_pct": last.get("atr_pct", 0.0)` 추가.

### 게이트 로직 (2가지 적용 지점 중 택1 또는 병행)

**(A) score_signal 내부 하드 게이트** — 가장 강력. 시그니처에 인자 추가:
```python
def score_signal(ind, min_atr_pct=0.0, bb_mode="current"):
    ...
    atr_pct = ind.get('atr_pct', 999)  # 데이터 없으면 통과(하위호환)
    if atr_pct < min_atr_pct:
        return -999   # 변동성 미달 → 진입 원천 차단
```
- `-999`를 쓰면 임계치(12)에 절대 도달 못 함. 청산·매도신호 판정에는 영향 없음(진입 스캔만 total_score로 필터).

**(B) 유니버스 빌드 단계 필터** — `data_builder.build_market_data()`에서 일봉 `atr_pct` 계산 후 `MIN_ATR_PCT` 미만 종목 skip. 스캔 대상에서 아예 제외해 API·연산 절감.

> 권장: **(B) 유니버스 필터 우선**(효율적·스테이블코인 근본 차단), 백테스터 검증은 (A)로 하는 것이 간단.

### 임계값 (config 신규 상수)
```python
MIN_ATR_PCT = 2.0   # 일봉 ATR이 종가의 2% 미만이면 진입 제외
```
- 근거: 익절 목표가 6%인데, 일봉 ATR%가 2% 미만이면 48h 안에 6% 도달 확률이 낮음(스테이블코인은 <0.1%). 2%는 보수적 하한. 1.5~3.0 스윕은 param-optimizer에 위임.
- **과적합 경고**: ATR 임계를 최근 시장 변동성에 맞춰 좁히면 레짐 변화에 취약. 90일+180일 두 구간에서 모두 EV 개선될 때만 채택.

### 백테스트 가능 여부: **O** (OHLCV의 high/low 필요 — 이미 fetch됨. backtest.py `row_to_ind`에 `atr_pct` 추가만 하면 됨)

## 실험 3 — 진입 위치 필터 (추세 내 눌림목 깊이)

### 가설
"상승추세"라도 (a) 밴드 상단·(b) 최근 고점 바로 밑에서 추격 진입하면 EV 음수. **얕은 눌림(고점 대비 -3~-10%)**에서 진입해야 승률이 오른다.

### 지표: 고점 대비 거리 (`pullback_pct`)
`data_builder`/backtest에서 계산 가능(추가 API 불필요):
```python
# 최근 N봉(예: 일봉 20봉) 고점 대비 현재가 낙폭
recent_high = df["high"].rolling(20).max()
pullback_pct = (df["close"] / recent_high - 1) * 100   # 음수(고점 아래)
```
`get_latest_indicators`에 `"pullback_pct"` 추가.

### score_signal 반영 (bullish일 때만)
```python
pb = ind.get('pullback_pct', 0.0)
if bullish:
    if -10 <= pb <= -2:   score += 2   # 얕은 눌림 = 최적 진입 위치
    elif pb > -0.5:       score -= 1   # 고점 바로 밑 추격 = 위험
    elif pb < -20:        score -= 1   # 추세 훼손 의심(깊은 하락)
```

### 검증 방법 (실증 우선)
- **먼저 백테스트가 아니라 로그 분석으로 가설 검증**: 매수 시점의 `pullback_pct`를 재계산(과거 OHLCV 재조회)해 손익과의 상관을 본다. 이 스펙 단계에서는 매수 로그에 pullback이 기록돼 있지 않아 계산 불가 → **backtest.py에 컬럼 추가 후 진입 시점 pullback을 trade dict에 기록**하고 구간별 EV를 뽑는 방식 권장.
- 상관이 확인되면 위 가·감점 채택, 아니면 폐기.

### 백테스트 가능 여부: **O** (단, 먼저 상관 검증 필요 — "검증 후 채택")

## 실험 4 — 유니버스 재정의

### 현행 (`data_builder.get_top_volume_tickers`)
24h **거래대금 상위 20종**을 매 스캔 추종. 스테이블코인만 제외.

### 구조적 문제
1. 거래대금 상위 = **이미 급등해 관심이 쏠린 종목** → 고점 추격 편향(실험 3 문제와 연결).
2. 거래대금 상위에 스테이블코인·신규상장 펌핑 코인이 자주 진입 → 변동성 왜곡(실험 2 문제와 연결).
3. 유니버스가 매 사이클 바뀌어(추종) 신호 일관성·백테스트 재현성 저하.

### 대안 (백테스트로 A/B 비교)
- **U0 (현행)**: 거래대금 상위 20.
- **U1 (변동성 필터 적용)**: 거래대금 상위 40 중 `atr_pct >= MIN_ATR_PCT`인 상위 20. (실험 2와 결합)
- **U2 (추세지속성 상위)**: 거래대금 상위 40 중 "일봉 정배열(es>em>el) 유지 봉 수"가 큰 상위 20. 추세 성숙 종목 우선.
- **U3 (고정 유니버스)**: `MARKET_COINS`(대형주 20종) 고정 — 재현성·유동성 안정. 백테스트-실전 정합성 최상. 단 알트 상승장 알파 포기.

### 검증 방법
`backtest.py`의 `DEFAULT_TICKERS`를 각 유니버스 후보 목록으로 바꿔 EV 비교. 단 **거래대금 상위는 과거 시점 재구성이 어려움**(생존편향) → U0의 과거 유니버스는 근사만 가능. 실전 유니버스 A/B는 섀도우 로그(실험 5)로 병행 검증하는 것이 정확.

### 백테스트 가능 여부: **U2/U3 = O**, **U0/U1 정확 재현 = △**(생존편향·과거 거래대금 순위 복원 한계). 실전 섀도우 로그 병행 권장.

## 실험 5 — 시뮬-실전 필터 정합성 + 섀도우 로그

### 현 괴리 지점
시뮬 모드는 (1) 레짐 필터(BTC EMA 하락 차단)와 (2) F&G 극단값 차단을 **바이패스**한다(데이터 축적 목적). 따라서 시뮬 로그의 EV는 "실전 게이트를 통과했을 트레이드"보다 **낙관/비관 방향 불명확한 편향**을 갖는다. 특히 하락 레짐에서 진입한 트레이드가 시뮬에는 포함되나 실전에는 없음 → 시뮬 EV가 실전보다 나쁠 수 있음(음의 편향).

### 섀도우 로그 스펙
매수 로그(`_log_trade`의 buy 레코드)에 **진입 시점의 게이트 상태**를 추가 기록(진입 차단은 하지 않음, 기록만):
```python
{
  ..., "type": "buy",
  "shadow": {
     "regime_ok": <bool>,        # 레짐 필터 통과 여부
     "fg_block": <str|null>,     # F&G 극단 차단 사유
     "atr_pct": <float>,         # 진입 시 일봉 변동성
     "pullback_pct": <float>,    # 진입 시 고점 대비 낙폭
     "bb_pct": <float>,
  }
}
```
### 분석 방법
청산 후, `regime_ok=True`인 트레이드만 필터링해 EV를 재계산 → "실전 필터 적용 시 EV"를 시뮬 데이터로 역추정. `regime_ok=True` 부분집합의 EV가 전체보다 유의하게 높으면 **레짐 필터가 실제로 알파를 갖는다**는 증거.
- 마찬가지로 `atr_pct`·`pullback_pct`·`bb_pct` 구간별 EV를 실전 데이터로 직접 검증 → 실험 1·2·3의 임계값을 백테스트가 아닌 **실측**으로 튜닝 가능(과적합 위험 최소).

### 백테스트 가능 여부: **O (분석 전용)**. 코드 변경은 로그 필드 추가뿐, 매매 동작 무변경 → 리스크 극히 낮음. **가장 먼저 배포해도 안전.**

## 실험 6 — param-optimizer 재실행 시점

`scripts/backtest.py` 스윕을 **다시 돌려야 하는 조건**:

| 반영된 실험 | backtest.py 수정 필요 | param-optimizer 재실행 필요 | 이유 |
|-----------|--------------------|------------------------|------|
| 실험 1 (BB 부호) | O (`--bb-mode` 인자, `row_to_ind`엔 bb_pct 이미 있음) | **O** | 점수 분포가 바뀌면 임계치·TP/SL 최적점 이동 |
| 실험 2 (변동성 게이트) | O (`row_to_ind`에 `atr_pct` 추가, `--min-atr` 인자) | **O** | 진입 종목 집합 변화 → 전 파라미터 재최적화 |
| 실험 3 (진입 위치) | O (`row_to_ind`에 `pullback_pct` 추가) | **O** (단 상관 검증 후) | 점수 재분포 |
| 실험 4 (유니버스) | O (`DEFAULT_TICKERS` 교체) | **O** | 종목 집합이 성과의 지배 요인 |
| 실험 5 (섀도우 로그) | X | **X** | 매매 동작 무변경, 분석 전용 |

**원칙**: score_signal의 출력값이나 진입 종목 집합을 바꾸는 실험(1·2·3·4)은 **반드시 param-optimizer 재실행**. 임계치(12)·TP(6)·SL(4)·MAX_HOLD(48h)는 현 점수 분포에 맞춰 튜닝된 값이므로, 점수 체계가 바뀌면 무효가 된다.

### 채택 추천 (1~2개, 즉시 진행)
1. **실험 5 (섀도우 로그) — 지금 바로**. 매매 무변경·리스크 없음. 실전 데이터로 실험 1/2/3 임계값을 실측 튜닝할 수 있어, 이후 모든 실험의 과적합 위험을 낮춘다. **전제조건 성격**.
2. **실험 2 (변동성 게이트) — 섀도우 로그로 `atr_pct` 구간별 EV 확인 후**. 스테이블코인 flat-청산(USDT 14회 실증)을 근본 차단하고, 점수-EV 무상관 문제의 한 축(변동성 없는 종목의 무의미 점수)을 제거. backtest.py에서 `--min-atr` 스윕 → param-optimizer 재실행.

### 경고
- **실험 1·2·3·4는 절대 동시에 넣지 말 것**. 개별 토글로 backtest EV를 하나씩 측정한 뒤, 유의미한 것만 결합. 동시 도입 시 어느 변경이 효과인지 귀속 불가 + 조합 과적합.
- 점수-EV corr=0.062는 **현 점수 함수가 순위 신호로 실패**했음을 의미. 위 실험들은 대증요법이며, 근본적으로는 실험 5로 "어떤 피처가 실제로 EV와 상관있는가"를 실측한 뒤 score_signal을 그 피처 중심으로 재구성하는 것이 정공법이다.
- param-optimizer 재실행 시 **단일 최근 90일 최적화 금지**. 반드시 90일+180일(또는 서로 다른 레짐 2구간) 교차검증에서 모두 양(+) EV인 조합만 채택(README 6/22 재튜닝 선례 준수).
